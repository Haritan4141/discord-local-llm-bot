## 結論と範囲

ユーザー申告の「選んだ場所と違う場所に置かれる・表示がおかしい」に一致する現象を、現行コードを使用したローカル再現で確認した。最優先の原因は、リアクション番号を現在の局面で解釈し直す処理と、入力・盤面更新・表示更新を一貫して管理できていない構造にある。

盤面の基本ルールとPNG描画の基礎は活用できる。操作方式、ゲームの状態管理、AI評価・実行方式を中心に改修するのが妥当。今回の作業は調査と資料更新であり、実装・設定・Botプロセス・コマンド登録は変更していない。Discordへの投稿や本番対局の操作も行っていない。

静的確認、既存テスト、実際のゲーム関数とイベントハンドラを使ったローカル再現、描画検証、Discord公式資料の照合を行った。再現時のDiscord通信は遅延・失敗を制御できるテスト用オブジェクトに置き換え、`src/bot.mjs` 自体はimportせず、対象リアクションハンドラだけを読み込んだ。ユーザーが経験した個々の対局のログとの照合は未実施であり、同一の原因だったとまでは断定しない。

## 優先度の高い不具合

### 1. 表示中の番号と異なるマスへの着手（P1・再現済み）

関連: `src/bot.mjs:615-645`、`src/othello/game.mjs:36-42,179-196`。

初期の選択肢は `0:D3 1:C4 2:F5 3:E6`。通常難易度で以下を再現した。

1. `1` を押す。C4に黒が置かれ、AIが応手する。
2. メッセージ更新が完了する前に、まだ初期表示の `0:D3` を見て `0` を押す。
3. 内部の選択肢は既に `0:C2 1:D3 2:F5 3:E6` になっており、**D3ではなくC2への着手が成功する**。

`handlePlayerMove()` のロックは同期的な着手・AI処理の終了直後に解除され、Discord更新中を保護しない。受信イベントには局面の版番号も座標もなく、番号から最新の合法手一覧を引き直している。後から到着した古い入力を識別できない。

ページ移動でも同じ現象を再現した。次ページの表示待ちに、旧ページの `0:B2` を選ぶと、新ページの `0:F6` に着手した。ページ移動にはロック自体がない。

**修正要件:** 操作に対局ID・局面の版・座標を含め、プレイヤー確認と合法手の再検証を行う。古い版の入力は新しい局面に読み替えず拒否する。処理単位の排他は表示の確定まで含める。ロックを延長するだけでは、ロック解除後に遅れて届く古い入力を防げない。

### 2. 画像と本文が異なる局面になる（P1・再現済み）

関連: `src/othello/game.mjs:108-128`。

PNG・番号・座標一覧はメッセージ取得前に作り、石数・手番は `await channel.messages.fetch(...)` の後で可変なgameから再計算している。取得待ちの間に別操作が進むと、異なる状態が一つのメッセージに混ざる。

上記の連続入力再現で、最初の編集は **PNGが黒3・白3、本文が黒4・白4** となった。画像は一つ前の局面で、内部状態はさらに先へ進んでいる。

**修正要件:** 一つの確定した状態スナップショットから、PNG・本文・操作部品のすべてを生成する。更新は対局単位で直列化し、古い更新が新しい表示を上書きできないようにする。

### 3. 通信失敗後の表示・操作復旧が不十分（P1・一部再現済み）

関連: `src/othello/game.mjs:55-105,118-129`、`src/bot.mjs:643-649`。

- メッセージ取得失敗を `catch(() => null)` で無条件に無視する。着手済みの内部状態と古い画面が残る状況を再現した。対局も入力ルーティングも有効なままになる。
- 編集失敗では内部状態を進めたままハンドラ外周へ例外が伝わる。コンソールの `reaction error` 以外に、プレイヤーへ復旧状態を示す経路がない。
- リアクションの同期完了前に `reactionStateKey` を保存する。全4個の追加が2回ずつ失敗した後、同じ状態で次の表示更新を実行しても追加試行は増えなかった（8回のまま、操作部品0個）。
- 他人のリアクションを消すには `Manage Messages` が必要だが、その削除失敗は無言で無視される。残ったリアクションを再度押すと追加ではなく取り消しになるため、操作が反応しないように見える可能性がある。実際のサーバー権限不足は未確認。

**修正要件:** 取得・編集・操作部品更新の失敗を区別し、復旧中は入力を進めない。再試行は同じ確定局面の再表示だけを行い、着手を二重実行しない。メッセージ削除や権限喪失時は対局を明示的に終了または無効化する。

### 4. 「最強」AIの評価方向が逆（P1・再現済み）

関連: `src/othello/ai.mjs:24-37,73-119`。

`evaluateBoard()` は「黒＝プレイヤーに有利なほど正」と明記され、実装も同じ方向。ところがminimaxは白＝AIで最大化し、黒で最小化する。根の着手選択も最大値を選ぶ。したがって探索がプレイヤーに有利な方向を目的にしている。

また、満盤・両者合法手なしの終局も位置重みなどを含む通常の評価関数へ渡す。終局の勝敗・石数差を優先する評価がないため、符号の修正だけでは不十分。

次の局面（0=空、1=黒、2=白、白の手番）で、現行maxがD7を選ぶことを確認した。独立した終局までの探索ではA3なら白40・黒24で勝てるが、D7では白26・黒38で負ける。

```text
22221111
22222211
02222211
21222211
22111211
22221111
22201002
22011100
```

終局評価の別例として、以下の満盤は黒30・白34で白勝利だが、`evaluateBoard()` は黒側に有利な `+244` を返した。

```text
12222222
12222222
12122112
11212212
11221122
11212122
11222211
11111111
```

`easy` はランダム、`normal` は反転数最大、`hard` は反転数＋角・辺の加点であり、後二者は読み合いを行わない。「最強」は深さ5固定で、時間制限・中断・ワーカーへの分離がない。

31石・白の合法手17個の局面では、maxの同期探索がMAINで約744～779msかかり、直前に登録した `setImmediate` も約755ms待たされた。初回実行では約1.1秒のサンプルもあった。これは当該局面・環境での値であり、全局面や本番機の上限ではない。

探索内ではパスでも深さを1減らす。深さを「実際の着手数」とするなら維持すべきであり、パスを含む局面でも一貫した読みの深さになるよう仕様を定義する必要がある。

**修正要件:** 評価値の視点を白側など一つに統一する。終局評価を通常の局面評価から分ける。難易度ごとの予算を定め、AI計算をBotのイベント処理から分離する。

### 5. パスで勝敗表示を上書きする（P2・再現済み）

関連: `src/othello/game.mjs:132-173`。

`checkGameEnd()` は勝敗を `game.note` へ設定するが、同じ `runAiIfNeeded()` 内でパスが発生していると、最後の `if (note) game.note = note` が勝敗を上書きする。

初期盤面から合法手のみで到達した対局で、黒2・白44、両者合法手なし、`ended=true` にもかかわらず表示が **「パス: あなた (黒)」だけ** になることを確認した。黒の着手順（AIはnormal）は次のとおり。

```text
D3 B3 B1 D2 F3 B4 B5 D1 F4 D6 H2 C4 A5 G5 A4 C7 D8 E7 B7 F6
```

**修正要件:** 勝敗、直前の着手、パス通知を別々の状態として持つ。終局表示では手番を表示せず、結果を優先する。自動パスの進行もDiscordから独立してテスト可能にする。

### 6. 対局の寿命と後始末がない（P2・再現・コード確認済み）

関連: `src/othello/game.mjs:15-16,132-143,199-232`。

- 対局終了時はメッセージIDの逆引きだけを消し、`othelloGames` 本体には対局を残す。
- 開始応答が期限切れ（10062）になると、表示できなかった対局がMapに残る。ローカルでMapが1件増えることを確認した。
- 放置期限・投了・同一ユーザーの対局数制御・盤面メッセージ削除時の後始末がない。
- Bot再起動で対局状態が失われる一方、Discordには過去の操作表示が残る。再起動後の入力に期限切れを案内する仕組みがない。
- 終局後も `formatOthelloStatus()` は「手番: AI/あなた」を表示する。

**修正要件:** 開始・進行・復旧・終了・期限切れを明示的な状態として管理する。終了時は表示を無効化し、Mapとタイマーを解放する。初期改修では再起動をまたぐ対局復元を必須とせず、失効を明確に案内する設計でよい。

## 活かせる部分と表示改善

- `board.mjs` は初期配置、8方向の挟み判定、合法手列挙、反転、石数計算を分離できている。ランダム盤2,000枚を独立した参照実装と比較し、合法対局1,000局で反転・石数の不変条件を確認した。現時点で通常入力に対する盤面ルールの破綻は見つかっていない。
- `applyMove()` や色のヘルパー自体は不正入力を検証しない。現在の通常着手経路は合法手を再計算しているため、直接の原因とはしない。改修時も外部入力を検証する境界を維持・明確化する。
- `render.mjs` の出力は400×400 RGBAの正常なPNGで、主要チャンクとCRCを検証済み。初期の `0:D3 / 1:C4 / 2:F5 / 3:E6` は画像上でも正しい。
- 描画はOSフォントや外部描画サービスに依存しておらず、この軽さは維持できる。
- 画像にA-H・1-8の座標軸がなく、1桁の番号しか描けない。縮小表示では番号が読みにくくなる。座標軸、直前の着手、合法手の目印を追加する余地がある。
- 描画に不正なラベルが渡ると石の上もマーカーで覆うため、空マス限定の防御を入れる。現行の正しい合法手入力では発生していない。

## 未確定・除外した仮説

- `runAiIfNeeded()` の10回上限は合法な連続パス・AI連続着手を途中で切る懸念がある。ただし今回のnormalによる3,000対局では停止を再現しなかった。上限警告2件はいずれも正常な終局と同じ反復で出ており、警告だけから停止不具合と断定しない。
- `files` だけを渡す画像更新で過去の画像が際限なく積み重なる、という仮説は採用しない。導入済みdiscord.js 14.25.1の `MessagePayload` を通信なしで生成し、送信attachmentsが新規画像だけの `[{id:"0"}]` になることを確認した。
- 現在のDiscordサーバー権限、ネットワーク遅延、実際の利用PC/スマホでの表示、稼働中Botへの新コード反映状態は今回確認していない。ローカルの `bot.log` は2026-05-31の古い記録であり、今回の症状の裏付けには用いない。

## 推奨する改修構成・操作

### 操作

`/othello [difficulty]` の入口を維持し、数字リアクションから **「D3」「C4」など座標を直接表示するボタン** へ移行する案を推奨する。盤面にも同じ座標軸を表示する。

通常のメッセージとPNGに既存のMessage Componentsを組み合わせればよい。1行最大5ボタン、従来形式は最大5行なので、例えば合法手20個までを4行、最下行をページ切替・投了などに使い、それを超える候補はページ化する。8×8の全マスをボタンにする構成は採らない。選択メニュー方式なら最大25候補ごとのページ化が代替案となる。

数字を座標へ変えるだけでなく、部品の `custom_id` に対局ID・版・操作・座標を入れることが重要。入力を受け付けたら速やかに応答し、AI思考中・表示更新中を明示する。ユーザーに見せる文言に内部の版番号等は出さない。

### 内部構成

| 責務 | 改修方針 |
| --- | --- |
| 盤面ルール | `board.mjs` を基礎として維持。外部入力は座標で受け、最新の合法手から反転を再計算 |
| 対局進行 | Discordに依存しない状態遷移。プレイヤー手番・AI思考・表示復旧・終了等を区別 |
| AI | 評価視点と終局評価を修正。時間予算付きの探索をworker等で分離 |
| Discord操作 | 部品の解析、本人・対局・メッセージ・版の確認、即時応答、直列処理 |
| 表示 | 一つの状態スナップショットから本文・画像・部品を生成 |
| セッション管理 | 対局数、放置期限、開始失敗、終了、メッセージ削除、再起動後の失効を管理 |

部品操作は現在の `InteractionCreate` 冒頭で `isChatInputCommand()` 以外をreturnしている箇所より前でルーティングする必要がある。チャット、画像・音楽生成などの既存ハンドラは維持する。リアクション処理と専用Intent・権限案内の整理は、他機能の使用有無を確認してから行う。

### 実装・検証の順序

1. 今回再現した誤着手、混在表示、パス結果上書きを回帰テストとして固定する。
2. ルール・対局進行・セッションを整理し、AIの評価方向と終局評価を修正する。
3. 座標付きの部品操作と一貫した表示更新へ置き換える。
4. 通信失敗・再試行・期限切れ・終了処理、AI計算の時間制御を仕上げる。
5. 全テストとDiscord実機確認を実施し、README・help・コマンド説明を実装と揃える。コマンド定義を変更する場合に登録が必要。

### 受入条件

- 指定した座標以外へ着手しない。古い入力、連打、ページ切替直後、他人の操作を適切に拒否する。
- 画像・石数・手番・合法手・操作部品が常に同じ局面を示す。
- AI・プレイヤーそれぞれのパス、連続パス、空マスの残る終局、引き分け、投了を正しく処理する。
- 表示失敗後に局面を二重に進めず復旧できる。削除済みメッセージや権限喪失を放置しない。
- 放置、終了、開始失敗で対局が際限なく残らず、再起動後の操作には失効を案内する。
- AIが自分の勝利を優先し、思考中も他のDiscord操作や通常チャットの受付を妨げない。
- PC・スマホのDiscordで座標が読み取れ、着手場所とAIの直前の手を追える。
